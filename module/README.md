# bcw — модуль обхода DPI для KernelSU

Обход на nfqws2 со стратегиями по сетям, паузой в домашнем Wi-Fi, сторожем и откатом;
28 пресетов nfqws2-android с редактором; поиск стратегий `bcw` из WebUI (вкладка «Поиск», этап 3).
Только KernelSU и arm64. Спецификации: `docs/superpowers/specs/2026-11-01-bcw-module-design.md`,
поиск (этап 3) — `docs/superpowers/specs/2026-11-04-bcw-search-design.md`.

Откуда взяты пресеты, списки, блобы и скрипт сборки nfqws2 — `NOTICE.md`.

## Где что лежит на телефоне

| Путь | Что там |
|---|---|
| `/data/adb/modules/bcw/` | код модуля: `bin/bcw`, `bin/nfqws2`, `lua/`, пресеты, списки и блобы |
| `/data/adb/bcw/` | данные: `settings.conf`, `lists/`, `strategies/`, `networks.tsv`, `home_wifi.list`, `logs/`, `runs/` |

Удаление модуля стирает и `/data/adb/bcw/`.

## Проверка на телефоне, веха 2а (из Termux)

Все команды — в Termux на телефоне. Для краткости:

```
B=/data/adb/modules/bcw/bin/bcw
```

1. **SSID (риск R1) — до установки.** На Wi-Fi: `su -c 'cmd wifi status'` — в выводе должна быть
   строка `Wifi is connected to "<имя сети>"`. Пришлите вывод.
2. **Установка.** В менеджере KernelSU **отключите** nfqws2-android (переключатель), затем
   «Установить из хранилища» → `bcw-module-v0.1.0.zip` → перезагрузка.
3. **Служба.** `su -c "$B ctl status"` → `"state":"running"`, `"strategy":"default"`.
4. **Обход.** rutracker.org открывается в браузере — на Wi-Fi и на мобильной сети.
5. **Пакеты nfqws2 не уходят в очередь повторно.** Откройте пару сайтов, затем
   `su -c 'iptables -t mangle -L dpi_post -v -n | head -6'` — у третьего правила
   (`mark match 0x40000000/0x40000000 … RETURN`) счётчик пакетов больше 0, и
   `su -c 'iptables -t mangle -L dpi_unmark -v -n'` — счётчики больше 0.
6. **Стратегии по сетям.** На Wi-Fi:
   ```
   su -c "$B ctl settings set NET_STRATEGY 1"
   su -c "$B ctl strategy apply alt --network"
   su -c "$B ctl status"
   ```
   → `"strategy":"alt"`. Переключитесь на мобильную сеть, через ~10 с `ctl status` →
   `"strategy":"default"`; обратно на Wi-Fi → снова `alt`.
7. **Пауза дома.** На домашнем Wi-Fi (подставьте имя сети):
   ```
   su -c "$B ctl settings set HOME_WIFI 1"
   su -c "$B ctl home add 'Имя сети'"
   su -c "$B ctl status"
   ```
   → `"state":"paused_home"`. `su -c "$B ctl home resume"` → `"state":"running"`.
   Уйдите на мобильную сеть и вернитесь на домашний Wi-Fi → снова `paused_home`.
8. **Стратегия с ошибкой — запасная.** Неверный ключ nfqws2 проверка отвергает, и обход
   остаётся на рабочей стратегии:
   ```
   su -c "$B ctl settings set DEFAULT_STRATEGY no_such"
   su -c "$B ctl status"
   ```
   → ответ `settings set` с `"warning"`, `ctl status` → `running` на `default`. Верните:
   `su -c "$B ctl settings set DEFAULT_STRATEGY default"`. (Откат при падении nfqws2 в первые
   10 с проверен тестами; вызвать такое падение на телефоне нарочно нечем.)
9. **Сторож.** `su -c 'kill -9 $(pidof nfqws2)'`, через 10 с `ctl status` → `running`;
   `su -c "$B ctl logs service --tail 5"` → строка `restart сторож: …`.
10. **Перезагрузка.** После перезагрузки `ctl status` → `running` без ваших действий.
11. **Без дублей.** `su -c "iptables-save | grep dpi_ | sort > /data/local/tmp/a"`, трижды
    `su -c "$B ctl restart"`, `su -c "iptables-save | grep dpi_ | sort > /data/local/tmp/b"`,
    `su -c "diff /data/local/tmp/a /data/local/tmp/b && echo без изменений"` → `без изменений`.
    `su -c "$B ctl stop"` → `su -c "iptables-save | grep -c dpi_"` → `0`; `su -c "$B ctl start"`.
12. **Поиск рядом с обходом.** Запомните `su -c 'pidof nfqws2'` и `ctl status`, затем
    ```
    su -c "$B -w 254 scan -d rutracker.org -p tls12 | $B check -d rutracker.org --take 3"
    ```
    Во время прогона сайты через обход открываются; поиск находит стратегии; после —
    тот же pid обхода в `pidof nfqws2` (среди прочих) и `"state":"running"`.
13. **Сосед.** (Необязательно.) Включите nfqws2-android и перезагрузитесь → `ctl status` →
    `"state":"blocked_neighbour"`; отключите его и перезагрузитесь снова.

Что прислать: вывод шагов 1, 3, 5, 6, 7, 8, 9, 11, 12 и `su -c "$B ctl logs service"`;
где не так — что видели.

## Проверка на телефоне, веха 2б (WebUI)

Установите `bcw-module-v0.1.0.zip` из релиза поверх прежнего в менеджере KernelSU и
перезагрузитесь. Откройте модуль bcw в KernelSU → значок WebUI.

1. **Состояние.** «Работает», сеть и стратегия совпадают с `ctl status`. «Остановить» →
   «Остановлено»; «Запустить» → «Работает»; «Перезапустить» → снова «Работает».
2. **Стратегии.** Текущая отмечена «сейчас». Во вкладке «Сети» включите «Своя стратегия для
   каждой сети». Откройте `alt` → «Для этой сети» → во вкладке «Состояние» стратегия `alt`.
   (С выключенным тумблером «Для этой сети» запоминает выбор и предупреждает, что он не действует.) Поменяйте в поле TCP число `repeats=6` на `repeats=5` →
   «Сохранить» → в списке у `alt` отметка «изменён»; «Вернуть к исходнику» → отметка ушла.
3. **Ошибка в стратегии.** «Новый», имя `test1`, в поле TCP: `--nope` → «Сохранить» → под
   редактором красный текст «nfqws2 не принял стратегию: …», обход продолжает работать.
   Исправьте поле на `--filter-tcp=443` → «Сохранить» → у `test1` отметка «свой»;
   откройте → «Удалить».
4. **Сети.** На Wi-Fi: «Добавить текущую в домашние» + тумблер «Пауза в домашних Wi-Fi» →
   «Состояние» показывает «Пауза: …» и кнопку «Включить здесь сейчас» → нажмите → «Работает».
   Уберите сеть из домашних и выключите тумблер. На мобильной кнопки добавления нет.
5. **Списки.** Откройте «Сайты для обхода», добавьте строку `example.org` → «Сохранить» →
   число строк выросло на 1. Режим «Только сайты из списка» → после перехода на другую вкладку
   и обратно выбран он же; верните прежний.
6. **Настройки.** «Исходящих пакетов…» = `500` → «Сохранить» → под полем текст ошибки,
   значение не изменилось. `20` → сохраняется. Верните `15`. Внизу версии bcw и модуля.
7. **Журналы.** Служба → видны перезапуски и смены стратегии из шагов выше; «Только ошибки» →
   только строки с `error` (если ошибок не было — пусто); статистика над журналом. Ошибка
   сохранения из шага 3 в журнал не пишется — она показывается только под редактором.
8. **Обновление.** В менеджере KernelSU у модуля видна версия v0.1.0, ссылка на обновление
   не ругается.
9. **Удаление.** Удалите модуль в менеджере, перезагрузитесь →
   `su -c 'ls /data/adb/bcw; iptables-save | grep -c dpi_'` → «No such file or directory» и `0`.
   Затем установите модуль снова, если пользуетесь им.

Что прислать: где поведение не совпало — номер шага и снимок экрана или текст.

## Приёмка этапа 3 (поиск стратегий из WebUI)

Установите zip сборки поверх прежнего в менеджере KernelSU и перезагрузитесь. Все команды — в
Termux на телефоне, от root через `su -c '…'`:

```
B=/data/adb/modules/bcw/bin/bcw
```

Файлы каждого поиска лежат в `/data/adb/bcw/runs/<id>/`: `state.json` (ход и итог), `undo.json`
(что отменять при откате), `job.log` (журнал задания). Списки доменов для проверки —
`search-general` («Общие») и `search-youtube` («YouTube»); прочитать:
`su -c "$B ctl list get -- search-general"`.

Команды поиска из Termux (то же, что делает вкладка):

- `su -c "$B ctl search start [--enable-net-strategy] [-- <пресет>]"` — запуск; без пресета берётся
  стратегия сети или `DEFAULT_STRATEGY`;
- `su -c "$B ctl search status"` — ход последнего поиска;
- `su -c "$B ctl search stop"` — остановить;
- `su -c "$B ctl search runs"` — последние 10 поисков;
- `su -c "$B ctl search report -- <id>"` — отчёт поиска.

1. **МегаФон, основа `default`.** Мобильная сеть МегаФон. Откройте вкладку «Поиск»: «Сеть» —
   МегаФон, «Основа» — `default`. Если стратегии по сетям выключены, под полем подсказка, а
   «Найти» спросит про их включение — согласитесь. Нажмите «Найти»: идёт шкала `N / M` и
   время `мм:сс / 5:00`, укладывается в 5 минут, итог «Применено и проверено», в «Найдено»
   строки `tls`/`http`/`youtube`. Откройте видео в YouTube — оно идёт. Проверьте:
   `su -c "$B ctl search status"` и `su -c 'ls /data/adb/bcw/runs/*/'` (три файла). Пришлите
   снимок итога и вывод `search report`.
2. **Закрыть WebUI во время поиска.** «Найти», через 20–30 с закройте WebUI (и смахните
   приложение), подождите минуту, откройте снова → вкладка «Поиск»: поиск идёт (шкала
   продвинулась) или закончился с итогом. Если задание оборвалось вместе с WebUI —
   `su -c "$B ctl search status"` и хвост `su -c 'tail -n 30 /data/adb/bcw/runs/<id>/job.log'`
   пришлите (риск R3).
3. **«Стоп».** «Найти», во время перебора («Перебор: …») нажмите «Стоп» → итог «Остановлено».
   Проверьте, что ничего не применено: `su -c "$B ctl status"` — стратегия прежняя;
   `su -c "$B ctl strategies"` — нового пресета нет; запись сети в
   `su -c 'cat /data/adb/bcw/networks.tsv'` не изменилась.
4. **Смена сети.** «Найти» на мобильной сети, во время поиска включите Wi-Fi → итог «Сеть
   сменилась — найденное не применено». Выключите Wi-Fi, если он не нужен.
5. **Откат.** Нужен домен, который поиск находит, но обход потом не открывает. Во вкладке «Поиск»
   в поле «Общие» оставьте один такой домен → «Сохранить», «Найти». Ожидается итог
   «Откат: …» (или «Применено частично»), после него `su -c "$B ctl status"` — прежняя стратегия,
   `NET_STRATEGY` и запись сети как до поиска (`su -c 'cat /data/adb/bcw/networks.tsv'`),
   служба `running`. Затем «По умолчанию» для «Общие» (или верните свои домены). **Если такой
   домен не нашёлся — шаг пропускается с пометкой: откат покрыт тестами
   `engine/src/search/apply.rs`.**
6. **Обход и поиск рядом.** Пока идёт поиск, обход не прерывается: в Termux
   `su -c "$B ctl status"` — `"state":"running"`, а `su -c 'iptables-save | grep -c dpi_'`
   одинаково до поиска, во время и после (дублей правил нет). Откройте любой заблокированный
   сайт во время поиска.

Что прислать после каждого шага: номер шага, снимок экрана вкладки «Поиск» и вывод
`search status`/`search report` (для шагов 2 и 5 — ещё `job.log`).
